# 操作系统：进程调度与死锁

## 从就绪到运行
进程控制块保存进程标识、寄存器快照、调度信息和资源引用。处于就绪态的进程拥有执行所需的资源，只等待 CPU。运行中的进程请求尚未就绪的 I/O 时转入阻塞态；I/O 完成后重新进入就绪队列，调度器随后决定何时使它运行。

## 等待时间与周转时间
周转时间等于完成时刻减到达时刻。对只有一段 CPU 突发且不阻塞的作业，等待时间等于周转时间减运行时间。三个作业 A、B、C 同时到达，运行时间分别为 8、2、1 毫秒。按 A、B、C 顺序先来先服务时，等待时间分别为 0、8、10 毫秒，平均为 6 毫秒。若已知运行时间并按非抢占式短作业优先调度，顺序变成 C、B、A，平均等待时间降为 4/3 毫秒。

## 时间片轮转
轮转调度让就绪队列队首运行至多一个时间片。未完成的进程返回队尾，阻塞的进程暂时离开队列。缩小时间片有利于互动响应，但会增加上下文切换开销；时间片足够大时，轮转在一批同时到达的 CPU 密集作业上接近先来先服务。调度前应区分响应时间和周转时间。

## 死锁的必要条件
死锁需要互斥、占有并等待、不可抢占、循环等待四个条件同时成立。举例：线程甲持有锁 A 请求锁 B，线程乙持有锁 B 请求锁 A。若两把锁都是独占的，且只有持有者释放后别人才能取得，两个线程都无法前进。在每类资源只有一个实例的资源分配图中，环可判定死锁；多实例情况下，出现环不足以作此判断。

## 预防、避免与饥饿
给锁规定全局顺序并要求所有线程按同一顺序申请，可破坏循环等待条件。银行家算法则在批准请求前模拟分配，检查是否还存在安全完成序列。不安全状态表示无法保证所有进程安全完成，并不等于此刻已经死锁。饥饿是某个进程长期得不到服务，其他进程可能持续推进；可用优先级老化缓解。复述时请分别指出改变调度策略和改变锁协议能解决什么问题。
