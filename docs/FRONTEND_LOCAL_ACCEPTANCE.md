# 原版工作台本地验收

React 工作台保留仓库现有布局、配色、资料卡片、双窗、知识图谱和报告页面，已接通本地 LangGraph 后端。界面地址是 `http://127.0.0.1:5173/`；`http://127.0.0.1:18080/docs` 是后端接口文档，两者用途不同。

## 直接验收

启动前端 5173 和后端 18080 后即可打开工作台；如果服务已经运行，无须重复启动。服务端学生账号为 `student / 123456`，管理员为 `admin / admin123`。登录窗里的“学生演示”“管理员演示”进入浏览器本地演示，不使用后端；检查 LangGraph 时请使用账号表单登录。

1. 登录学生账号，资料库从服务端加载课程；可以上传仓库 `backend/data/sample_docs` 内的样例。
2. 点击“开讲”，选择目标知识点与听众，开始后显示服务端开场。
3. 讲解输入“我不会，卡壳了”，检查鼓励与右窗查证入口。
4. 点击“去右侧查证”，检查百科答复、可展开的真实引用和关联概念。
5. 切换为“严苛考官”，检查角色分隔提示及之后的追问风格。
6. 继续讲解，检查评估徽章、掌握度及图谱更新。
7. 写入未发送草稿后刷新；左右窗消息、角色、引用、评分和草稿应恢复。
8. 完成讲解后生成报告，检查四维图表、历史恢复、Markdown 导出及打印。
9. 在“记忆档案”中修改笔记，刷新后未同步的内容保留；点击同步后写入服务端。档案导出读取服务端内容。
10. 登录管理员，检查统计、四张表的实际名称与时间字段、JSON 和 SQLite 下载。日常验收不需要清理任何记录。

默认 `MOCK_LLM=true`，页面会标记“服务端规则演示”。记录仍写入真实 SQLite，教学流程执行真实 LangGraph，但语义评估使用离线规则。真实模型的教学质量、两轮高质量掌握判定和供应商时延，需在 `backend/.env` 配置模型后重启后端验收。百科与报告仍为既有基线实现。

## 重启服务

先停止本次已经运行的前后端进程，避免端口冲突。在仓库根目录执行：

```powershell
.\backend\.venv\Scripts\python.exe dev.py
```

启动器默认后端 18080、前端 5173。已有后端时只启动前端：

```powershell
.\backend\.venv\Scripts\python.exe dev.py --frontend-only
```

可用 `--backend-port` 和 `--frontend-port` 调整端口，前端地址会自动指向所选后端。当前后台 CORS 允许 localhost/127.0.0.1 的 5173、3000、4173；选择其他前端端口时需同步配置 CORS_ORIGINS。

`frontend/.env.example` 提供服务根地址示例；本机 `.env.local` 已配置为 18080，且被 Git 忽略。清空 VITE_BACKEND_URL 才会进入纯前端演示模式。启动器还支持通过 NODE_BINARY 指定 Node 路径，并能从当前捆绑 Python 的同级目录识别 Codex 自带 Node。

## 本次修复

| 问题 | 当前行为 |
| --- | --- |
| 双窗请求带额外字段导致 422 | 两窗仅发送 content，角色通过独立 PATCH 更新 |
| token/citation/memory_update 载荷读取不一致 | 读取 delta、citations[]、updates[] 与 done.message_id |
| 前端自己生成开场 | 在线模式调用服务端 opening/stream，不混入本地伪开场 |
| 在线登录后资料和历史为空 | 加载服务端课程、知识点、薄弱点、会话和报告，打开会话再恢复双窗历史 |
| 切换角色只改页面 | 后端保存角色和分隔消息，前端按服务端结果显示 |
| 笔记 405、导出 404 | 使用正确的笔记路径与服务端记忆/管理导出端点 |
| 管理表名称和时间为空 | 按四张表真实字段映射显示 |
| 中断后可能重复重发 | 先等待已接收的轮次结束，再刷新历史；核对新保存的用户消息后决定是否清空草稿 |
| 刷新丢失草稿或用旧浏览器数据覆盖服务器 | 本地只缓存草稿与未同步笔记，知识、评分、引用和已保存消息从服务端恢复 |
| 身份失效仍显示在线账号 | 401 清理失效令牌并重新打开登录；错误登录密码不会清除已有账号令牌 |
